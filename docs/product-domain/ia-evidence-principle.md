# IA 原则：证据跟随实体，共享管线才聚合

状态：**09-15 用户讨论后拍板生效**（「来吧」批准落地包 1→2→3）。本原则为平台 IA 争议的第一判据：
新页面/新 tab/新入口先过本原则，不再单点抱怨驱动搬移（09-12~09-15 四天五次 IA 动作的止血规约）。

## 原则正文

**P1 证据跟随实体。** 每个执行实体的流水/日志/投递证据，住在该实体自己的详情页内
（tab 或区块）。不为单实体另建独立「日志页」。

**P2 跨实体聚合视图的唯一合法理由：这些实体共享同一条管线，且运维需要跨实体提问。**
当前合法聚合仅两处：
- 接入健康概览带 + 事件流水（所有数据源共享 ingest→去重→路由→deliver 事件管线；
  运维问「哪条路由丢了 / 哪里有死信 / 谁在积压」必须跨源）；
- 任务看板 / WorkItem 投影（任务层跨执行体统一视图，09-12 已立，止于任务层）。

**P3 不建全局日志中心。** 工具/Agent/Workflow 的执行永远嵌套在 run 内，run trace 已是其证据的家；
全局中心=把各实体 trace 抄第二遍（与 WorkItem 想跨执行体统一是同一种诱惑的反面教材）。

## 实体 × 证据归属表（判例）

| 执行实体 | 证据 | 归属 | 跨实体聚合？ |
| --- | --- | --- | --- |
| 数据源 DataSource | 事件→路由→投递/死信 | 数据页·事件流水 tab + 源详情 | ✅ P2（共享事件管线） |
| 自动任务 | Invocation 历史 | 自动任务详情 | ❌ |
| 分析任务 | TaskRun→N Run | 任务详情 | ❌ |
| Agent | 会话+thinking+工具调用 | 对话/运行详情 | ❌ |
| Workflow/AgentFlow | Run+节点 trace | run 详情 | ❌ |
| Tool | 每次调用嵌套于 run | run trace + 工具详情 Usage（引用/关联 run 聚合） | ❌（P3） |

## 由原则导出的 IA 结构（09-15 合并案）

- **能力与资源 → 「数据」页，三 tab**：①接入健康（默认，概览带+源表+向导入口）
  ②数据资产（库存+目录挂载+被消费计数）③事件流水（P2 聚合）。
- 顶部导航**删除「数据接入」条目**；/data-sources* 全重定向到 /resources/data*。
  唯一入口=能力与资源→数据磁贴（IA 唯一归属，反冗余规约）。
- 设置→连接 不动（系统根凭据层，09-14 终版）。
- **接缝机制**（保证①②不分叉）：建源时目录选表/logstore 自动落 DataAsset（已挂载复用）；
  资产行显示「被 N 源消费」计数 chip 可跳；源详情显示资产引用卡（D5 已有）。
- 工具详情 Usage 补「关联 run/引用」列表（P1 判例的缺口补齐，独立小切片）。
