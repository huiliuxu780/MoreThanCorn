# 产品 UI / 交互 / 设计调研报告

> 调研对象：瓴羊 quickService 配置中心（config.quickservice.lydaas.com）—「Agent（新版）」工作台中的 **工作流（Workflow）编排** 及相关资源管理
> 调研时间：2026-08-21（约 15:30–16:00）
> 调研方式：真实浏览器登录账号后实操（ZCode 内置浏览器连接用户已登录会话），截图 + DOM 快照取证
> 证据目录：`screenshots/`（索引见文末）

## 1. 产品概览

- 产品名：瓴羊 quickService「配置中心」，工作台标签为 **Agent（新版）**。定位为客服智能体配置平台：场景（文本咨询/语音对话/客服辅助）+ 资源（知识库/技能/工作流/工具/评测/经验库/裁判库/标签/卡片）。
- 工作流编辑器基于 **React Flow**（画布含 `React Flow mini map` 元素），用于编排"开始→工具/模型/逻辑节点→结束"的对话处理流程。
- 页面全程带 **斜向水印**（"汇流 - 1205440079"，用户名+工号），属企业级防泄密设计。
- 技术栈仅从界面观察：React + Ant Design 风格组件 + React Flow 画布 + iframe 嵌套子应用（工具/工作流列表等内容运行在 iframe 中）。**后端/引擎不做推断**。

```

│   ├─ 消息中心 /notify-center
│   ├─ 系统设置 /system-settings
│   ├─ AI知识库 /knowledgeLibrary
│   ├─ 应用中心 /app-center
│   └─ 切换工作台（九宫格）
├─ Agent（新版）工作台
│   ├─ 二级导航
│   │   ├─ 场景：文本咨询 / 语音对话 / 客服辅助
│   │   └─ 资源：知识库 / 技能 / 工作流 / 工具 / 评测任务 / 评测集 / 经验库 / 裁判库 / 标签管理 / 卡片中心
│   ├─ 工作流列表 /intelligent-agent/ui/agent_store/blank/newWorkFlow
│   ├─ 工作流编辑器 /ui/agent_store/blank/newWorkFlowDetail?processId=<id>
│   └─ 工具 /intelligent-agent/ui/agent_store/blank/pluginBase
├─ 系统设置 /system-settings（基础配置/在线/热线/工单/会员设置/服务小记/应用及插件/客服助手）
│   └─ 应用及插件 → 应用管理 / 插件管理
└─ 插件调用日志 /ui/agent_store/blank/McpUseLog?type=service（新标签打开）
```

URL 规律：对象级页面用 query 参数（`processId`）标识当前对象；模块级页面为固定路径；**编辑器内状态（选中节点、抽屉）不反映在 URL**；浏览器返回可从编辑器回到列表。

## 4. 核心流程记录

### 4.1 工作流列表 → 编辑器
- 列表为**卡片网格**（非表格）：卡片含图标、名称、描述、右上标签（自主创建）、底部状态（`# 未发布`）与更新时间。
- 顶部工具条：搜索（名称）、筛选（全部）、排序（降序）、管理标签、**+ 创建工作流**（黑色主按钮，最突出）。
- 点击整卡进入编辑器（未观察到独立"名称链接 vs 行点击"差异）。

### 4.2 编辑器布局
- 顶栏（≈44px）：返回箭头｜橙色应用图标 + 名称"测试" + 状态标签`待发布`｜副标题"自动保存于 <本地时间>"（**自动保存指示器**，每次变更刷新）。右侧：检查图标（红点徽标=问题数）、历史版本（时钟）、保存（白）、发布（黑）。
- 画布：点状网格；节点白卡（圆角≈8px、轻阴影）；端口为左右蓝色小圆点；连线为贝塞尔曲线。
- 底部悬浮工具条（居中）：`+ 添加节点`｜适应画布｜自动布局｜（对齐/锁定类图标）｜缩放% 下拉｜放大｜（手型/选择图标）｜**试运行**（蓝色主按钮）。
- 小地图：底部居中、工具条上方。

### 4.3 添加节点
- 点击"添加节点"在按钮上方弹出**竖向 popover 菜单**，分组：
  - 信息处理：大模型、工作流选择、工作流执行、插件工具、客服工具、问题分类、Query改写、知识检索、数据查询、条件判断、工作流、图像生成
  - 代码编辑：代码编写、变量处理
- 每项 = 橙色/紫色小图标 + 名称。**无搜索框、无最近使用/收藏**（节点数仅 14，搜索缺位尚可接受）。
- 画布上**未验证拖拽添加**（菜单为点击式）。

### 4.4 节点配置（右侧抽屉，≈335px，全高）
通用结构：头部（节点图标+名称+`…`菜单+关闭×）→ 节点说明文案 → 分区（可折叠，chevron 旋转）→ 各分区内容。

| 节点 | 关键配置 |
|---|---|
| 开始 | 输入变量表：9 个系统变量（userQuery/chatHistory/userId/conversationId/chatId/file/fileType/fileUrl/fileName），列=变量名/类型/必填/描述，可+添加。说明文案明确三种入参来源 |
| 大模型 | 单次/批处理 Tab；模型下拉（13 模型，能力标签"文本生成/深度思考"，选中打勾）；输入变量表（+添加行：名称输入/类型下拉 Str./值"请输入或引用变量值"+⚙引用选择器/−删除）；提示词富文本编辑器（提示：输入"#"唤起变量选择器）；输出：输出格式下拉（Markdown）+说明、固定输出表（output/thought/answer）、"输出示例"按钮 |
| 问题分类 | 模型；必填 `*query`；**分类配置**：行=拖拽把手+分类名称(0/20 计数)+含义/场景/问法示例 textarea+删除；+添加；"其他分类"兜底分区；校验 alert"请输入分类名称" |
| 插件工具 | 工具在**建节点时绑定**（卡片显示 来源:插件市场 / 插件名称:企业微信）；输入表（含 Authorization 类授权变量）；输出为 **schema 树**（errcode/errmsg/version/document + 类型）；**流式输出**开关 |
| 代码编写 | 输入表；**内嵌深色代码编辑器**（行号、Python 模板、`args/ret` 注入约定注释）；"代码编辑器"按钮（外开 IDE）；输出表自定义 |
| 结束 | 输出变量表（名称/类型/值引用） |
| 变量处理 / 工作流执行 | 分组变量 / workflowCode 输入（卡片级观察，抽屉未逐一展开） |

- 选中节点在画布上加**蓝色描边**，并浮现 **▶ 单节点运行** 与 `…` 菜单。
- 变量引用：值列 ⚙ 图标 → 级联菜单（可见"系统变量 >"子级）；上游节点输出应同级提供（级联展开对自动化不友好，**子级内容未完整取证**）。

### 4.5 校验 / 测试 / 发布（状态机）
1. **试运行前置校验**：存在未配置/未连接节点时，顶部红色 toast「请先配置节点」，不进入运行。
2. **检查面板**：顶栏图标红点徽标=问题数；点开为「检查(9)」popover，逐条列出"节点未连接完整 / 节点未完整配置"（带节点图标）。**这是发布前检查的可视化清单，优秀设计**。
3. **发布**：弹出**软警告**模态「发布前未试运行 — 建议确认工作流正常运行后再发布」，三按钮：试运行 / 继续发布 / 取消。即：校验清单是硬门禁，试运行是软建议。
4. **保存**：手动"保存"按钮 + 顶栏"自动保存于…"时间戳并存（双保险）。
5. **历史版本**：时钟图标 → 右侧抽屉"历史版本"，空态"暂无历史版本"（推断：发布后生成版本，可回滚；**未验证**）。

### 4.6 工具 / 日志
- 工具页双 Tab：**工具插件 / MCP插件**（MCP 为独立一等公民，值得注意）。
- 右上：调用日志 / 管理标签 / + 创建插件（黑主按钮）。
- **插件调用日志**（新标签页）：搜索工具编码 + 筛选（归属插件/调用应用）+ 时间范围（默认最近 15 分钟）+ 表（工具名称/工具编码/状态/耗时ms/归属插件/调用应用/请求时间/操作）。当前账号无数据（空态"暂无数据"）。
- 系统设置→应用及插件→插件管理：平台插件卡片（任务管理/信息查询/语音转文本/…），每卡 **设置 / 停用**，分"已启用/已停用"两区。这是**平台级插件开关**，与 Agent 工作流的"插件市场工具"是两层体系。

| Error | 发布前软警告模态（橙叹号） |
| Running/Cancelled/Published | **未验证**（被前置校验拦截，且遵守安全约定不强行发布） |

## 6. 优秀设计（值得参考）

1. **检查清单徽标**：把"发布前校验"做成顶栏常驻红点+问题清单 popover，问题数即徽标数，点击可逐条定位——比"保存失败才报错"前置得多。
2. **自动保存时间戳外露**："自动保存于 3:34:46 PM"直接放在标题下方，用户永远知道草稿状态；同时保留手动保存按钮满足仪式感。
3. **节点卡片即摘要**：节点卡直接展示 输入/输出/模型/提示词 的配置摘要与类型 chip（Str./Int./Obj.），未配置显示灰色"未配置"——画布本身就是配置完整度地图。
4. **发布软警告三选项**（试运行/继续发布/取消）：尊重熟练用户，又给新手台阶。
5. **变量系统统一**：所有"值"列统一为"请输入或引用变量值"+⚙级联选择器；提示词用"#"内联唤起——同一套变量心智模型贯穿全编辑器。

## 7. 体验问题

1. 添加节点 popover **无搜索**，14 项尚可，扩展后会崩。
2. 节点面板分类只有 2 组且"信息处理"塞 12 项，分组粒度失衡。
3. 试运行被拦截时只给 toast，**不跳转/不高亮第一个问题节点**（检查清单与试运行拦截未联动）。
4. 单节点▶运行按钮无可见反馈（或同样被静默拦截），反馈缺失。
5. 工作流运行记录（Run/History）在编辑器内无入口，只有工具调用日志独立页——调试闭环弱。
6. 列表页筛选/排序为裸下拉，无已选条件回显；返回后状态保留未验证。
7. 编辑器内容跑在 iframe 中，偶发点击穿透/坐标错位（对本调研自动化不友好，对真实用户影响未知）。

## 8. 可借鉴 vs 不建议照搬

| 借鉴 | 不照搬 |
|---|---|
| 检查清单徽标 + 发布软警告 | 客服域专属节点（客服工具/经验库/裁判库） |
| 节点卡片配置摘要 + 类型 chip | 平台插件"设置/停用"双层工具体系（过重） |
| 自动保存时间戳 + 手动保存并存 | 全局水印（合规需求，非体验） |
| 变量引用级联 + "#"内联变量 | 系统设置大杂烩 IA（按客服业务历史堆积） |
| 右抽屉配置 + 分区折叠 | 列表页纯卡片无表格切换（规模上来后不够用） |

## 9. 落地结论（逐条回答）

1. **最值得借鉴的五项交互**：① 检查清单红点徽标；② 节点卡片配置摘要；③ 自动保存时间戳；④ 发布软警告三选项；⑤ 统一变量引用（⚙级联 + "#"内联）。
2. **只因它是大平台才需要的设计**：场景三入口（文本/语音/客服辅助）、平台插件启停、评测/裁判/经验库、标签管理体系、水印。
3. **不适合轻量 Workflow 产品的功能**：MCP 插件双 Tab（可后置）、批处理 Tab、流式输出开关、九宫格多工作台。
4. **我们的编辑器应保留**：React Flow 画布 + 点状网格 + 小地图 + 底部悬浮工具条；点击式添加节点（补搜索）；右抽屉配置；节点摘要卡；▶单节点测试；检查清单；自动保存指示。
5. **节点配置面板设计**：右抽屉≈340px；头部=图标+可编辑名称+…+×；说明文案一行；分区折叠（模型/输入/提示词或核心逻辑/输出）；输入输出统一"变量表"组件（名称/类型/值引用/删除）；值引用=级联（系统变量/上游节点）；富文本提示词支持"#"。
6. **Tool/Model/Connection 组织**：Tool 独立资源页（卡片+搜索+调用日志），节点内用"通用插件工具节点+选择具体工具"（本产品即此模式）；Model 平台预置下拉+能力标签，轻量期不做 provider 管理；Connection 挂在 Tool 详情（授权变量即连接凭证入口）。
7. **Schedule 与 Logs 位置**：本产品**无 Schedule**（触发=对话/API/子工作流）。Logs 建议：工具调用日志独立页 + 工作流 Run 历史放编辑器内"历史"抽屉（与版本抽屉并列 Tab），轻量期先做编辑器内运行记录。
8. **可直接成 Spec 的交互**：添加节点菜单结构；节点抽屉分区与字段表；变量表组件（含校验：必填*、名称计数 0/20、空值 alert）；检查清单数据结构（未连接/未配置两类）；发布软警告模态；自动保存指示；空态文案集。
9. **需源码/API 调研确认**：运行中画布状态与节点级日志结构；版本回滚机制；变量级联完整数据源；单节点运行的输入弹窗；MCP 插件 Tab 内容；iframe 子应用边界。
10. **第一期最小范围**：列表（卡片+搜索+新建）→ 编辑器（开始/结束/大模型/条件/代码/工具 6 节点）→ 右抽屉配置 → 变量引用 → 检查清单 → 试运行（含运行态与节点日志）→ 发布（软警告+版本抽屉空态即可）→ 自动保存指示。Schedule、MCP、批处理、评测全部砍掉。

## 10. 未验证事项与遗留

- 运行中/成功/失败画布状态、节点输入输出查看、重试/停止、Token 成本：未验证。
- 版本回滚、已发布 vs 草稿差异提示：未验证。
- 变量级联子菜单完整内容、"#"变量选择器弹层：自动化无法触发富文本事件，未取证（行为以页面提示文案为准）。
- 单节点▶无反馈原因：未确认（疑似同类前置校验静默拦截）。
- 列表页筛选保留/滚动位置保留、卡片 hover 操作菜单：未验证。
- **遗留数据**：大模型节点"输入"分区残留 1 行空测试变量行（自动化删除未成功，− 按钮疑似对唯一行禁用）。如需清理请在编辑器中手动删除该行；不影响发布校验结论。
