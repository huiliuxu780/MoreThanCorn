# Phase D｜产品面与治理

状态：大纲（开工前细化为可执行规格）
预估：持续投入（建议以 2 周为一个迭代切片）
前置：Phase C 已验收

---

## 1. 目标

补齐企业治理面与完整产品体验，并把本仓库从"原型"推向"可交付规格"：工程交付物落地、双轨残留清零。

对标：调研 02/03（壳层与交互）、07 §6–8（观测/评测/进化）、13（安全治理）、00 §19（交付物）。

## 2. 范围（细化前的边界承诺）

### D-1 Agent Workspace Shell 完整化
- Header 全量：身份/版本/草稿状态/自动保存时间/协作者（租约可视化）/发布下拉。
- 四 Tab（Agent搭建/运行观测/效果评测/进化）三型统一入口，替换目前只存在于画布抽屉的形态。

### D-2 预览增强
- 模型对比：双卡共输入框（会话级配置，不污染版本——调研 07 §2 结论）、对照选择器、复制变量。
- 清空会话、消息反馈（赞/踩仅存储）。

### D-3 观测与回放
- 指标聚合：首 token 耗时/平均响应/错误率/Token 消耗/会话数（基于 run_event + CallRecord）。
- 观测回放：选定版本 + 时间窗，重放输入与关键 Span（07 §6）。

### D-4 评测与进化（真语义）
- 评测：数据集版本化 + 字段映射 + Judge 三类（规则/模型/人评）+ 样本级分数报告。
- 进化：失败归因 → CandidatePatch（可查看/可撤销）→ 回归评测 → 人工审批 → 新草稿；进化永不直接改线上版本（07 §8）。
- "版本指标"面板恢复"进化"名实。

### D-5 治理
- RBAC 四角色（Viewer/Editor/Publisher/Admin）+ 资源权限（绑定/试运行/发布分权）。
- 审计日志表（发布/回滚/删除/解锁全留痕）。
- 编辑锁升级为租约（持有者/过期/续租/请求接管）。
- Credential 治理：Connection 密钥轮换流程；Trace 脱敏策略。
- 恢复 A-10 移除的词库/经验库区块（带真实实体与消费链路）。

### D-6 工程交付物与清退（调研 00 §19）
- `agent-domain.openapi.yaml`、definition/graph/node-registry/run-event 四份 JSON Schema、错误码表、MVP E2E 验收用例集。
- 前端测试框架建立（vitest）+ 关键纯函数覆盖。
- 质检页面 mock 清退（tasks/result-rules/agent-analysis 等对 mock-service 的依赖迁移到真实 API 或删除页面）。
- `mock-service.ts` / `mocks/` 最终删除。
