## 2. 架构重组（先拆房子再装修）

### 2.1 目录拆分（对齐前端既有约定：业务组件落 `components/wf/`）

```
src/features/designer/               # 新建（消灭空目录 src/features/）
├─ DesignerPage.tsx                  # 路由壳：<300 行，只负责加载/锁/布局编排
├─ canvas/
│  ├─ FlowCanvas.tsx                 # ReactFlow 装配：连线校验/重连/拖放/小地图
│  ├─ NodeCard.tsx                   # 唯一节点渲染器（见 §3）
│  ├─ edges.tsx                      # 边样式：控制流/错误分支/循环回边三态
│  ├─ layout.ts                      # 自动布局：现内联实现原样搬入；是否引入 dagre/elkjs 属新增依赖决策，实施时再定（当前 package.json 无此依赖）
│  └─ selection.ts                   # 框选/多选/对齐
├─ panels/
│  ├─ NodePalette.tsx                # 左侧节点面板（注册表驱动，按 family 分组）
│  ├─ Inspector.tsx                  # 右侧统一检查器（见 §4，消灭双路径）
│  ├─ Toolbar.tsx                    # 顶栏：版本徽标/保存态/发布门禁/编辑锁
│  └─ drawers/{Runs,History,Eval,Schedule,Agent,Evo}.tsx   # 8 抽屉各自成文
├─ schema-form/                      # GenericSchemaForm 升级为唯一配置渲染器
│  ├─ SchemaForm.tsx  renderers/     # x-control → 组件映射表（可注册扩展）
│  └─ validators.ts
├─ runtime/
│  ├─ RunOverlay.tsx                 # 运行态覆盖层（按 runId 派生，不写回图）
│  ├─ TestRunPanel.tsx               # 试运行 SSE + 节点单测
│  └─ useRunEvents.ts                # GET /runs/{id}/events?after= 重放
└─ store/
   ├─ draft.ts                       # Draft 业务态（撤销重做/脏标记/1200ms 自动保存）
   └─ ui.ts                          # 画布 UI 态（选中/缩放/抽屉开关）
```

- 设计器三层状态既有决策（画布 UI / Draft 业务 / Run 实时，运行态与 Draft 分离）**保留**，只是从 useState 散居变成显式 store（zustand 或 Context+reducer 二选一，倾向前者——体量小、无新基建负担）。
- 节点注册表仍来自服务端 `wfApi.nodeDefinitions()`（**前端不硬编码节点清单**是已验收资产，保持）。
- 删除清单：自研 Toast（统一 sonner）、`LEGACY_SIX_CLIENT` 迁移按钮（一次性工具，迁移已完成应下线或移入运维脚本）、`NodeCfgLoose` any 豁免（换 per-type 配置类型，从注册表 schema 推导）、`Date.now()%100000` ID（改 `crypto.randomUUID()`）。
- 旧图兼容：agent/agent-select/agent-exec 三类节点的**加载期一次性迁移改写**保留在加载层（独立 `migrate.ts`），渲染器不再认识它们。

### 2.2 验收方式

拆分是纯重构：视觉回归 24 屏 ≤0.5% 全绿 + 组件标准扫描 allowlist 只减不增 + 现有设计器相关测试全过，作为"拆分完成"的三类证据。这一步先于任何新功能。

## 3. 画布与节点卡展示设计（"展示效果"）

### 3.1 画布基底

沿用冻结令牌（16 号复刻规格，视觉回归断言已固化，不动数值）：画布底 `#EEF1F6`、点格 `#D9DEE7`/16px、节点卡宽 300、右抽屉 360、主色 `#3D6BFF` 仅限运行/链接/选中、错误 `#F56C6C`、未配置 `#B9C2CF`。**V2 的做法不是换视觉，而是把这些值全部落 CSS 变量/令牌文件**，组件只引用变量——既过现有断言，又终结 inline hex 双轨。

新增展示能力（竞品调研结论落地，`~/Documents/Codex/调研/workflow-ui-research/report.md`）：
- **小地图 + 缩放工具条**（ReactFlow 标配，当前缺失）；
- **端口类型着色**：输入/输出端口暴露数据类型（文本/记录/列表/数字…），连线时类型不兼容预防性提示（对齐调研结论"端口暴露输入输出类型并在连线时预防不匹配"）；
- **三态边**：控制流（实线）、错误分支（红虚线，D2 决策的错误分支配置项的视觉表达）、循环回边（灰虚线带 ↺ 标记，D4）；
- **分组容器**：GROUP 画布的成员节点容器化显示（已有 family 分组语义的视觉补齐）。

### 3.2 节点卡（统一结构，消掉巨型 switch）

```
┌────────────────────────────────┐
│ ⚙ 图标  节点名 (可改)        ⋮ │   ← 头部：类型图标+名称+菜单(复制/删除/单测)
│ 摘要行：配置回显（1-2 行灰字） │   ← 未配置显示"待配置"灰态(#B9C2CF)
│ ● 输入端口        输出端口 ●   │   ← 类型着色；错误分支多一个红色端口
│ 状态角标：⚠ 校验 / ▶ 运行中覆盖│
└────────────────────────────────┘
```

- **摘要行回显**是既有决策（07 §3.2 面板公共机制），V2 把每类节点的摘要生成器注册进注册表（`summary(cfg) → string`），不再写死在渲染器；
- **运行态覆盖层**：选中运行时按 runId 派生描边+状态色（Idle/Running/Success/Error/Waiting 五态固定颜色+图标+文字组合，调研结论），**不写回持久化图节点**（调研主文档 §5.3 红线）；
- 校验三处同源保持：卡红点 = 抽屉 issue = 顶栏角标（07 §3.2）。

## 4. 节点配置面板统一（消灭双路径）

**决策：`GenericSchemaForm`（注册表 schema 驱动）成为唯一渲染路径；原 `ConfigDrawer` 里的定制控件降级为"注册表字段渲染器"**——即 schema 里 `x-control: condition-builder` 就挂条件构建器组件、`x-control: prompt-area` 挂提示词组件。加节点只改注册表，不碰面板代码。

统一面板结构（所有节点一致，对齐调研的三栏框架右栏规范）：

```
┌─ 右抽屉 360px ──────────────────┐
│ 节点名 / 类型徽标        [单测] │
│ ── 配置区（schema 驱动）────── │
│   各字段：label+控件+行内校验    │
│ ── 公共机制区（每节点都有）──── │
│   execution：超时/重试/onError   │  ← D2 错误分支配置项的家
│   输出变量区（统一命名）          │
│ ── 校验摘要区（与顶栏角标同源）─│
└──────────────────────────────────┘
```

公共机制（07 §3.2 已定型，V2 全节点强制挂齐）：`execution{timeoutMs, retry{enabled,maxRetries,intervalMs}, onError: fail|skip|branch|default}`、输出变量、notice 内联、Test Run 覆盖层（按引用变量自动生成输入，替代"手填 mock JSON"的手绘做法）。

## 5. 逐节点配置详细设计（22 节点账本）

> 每节点：关键字段 → 控件形态 → 校验要点。字段控件全部走 §4 注册表渲染器；"引用"指变量级联（VarCascader，既有）。

### 输入/输出族
| 节点 | 关键字段 | 控件 | 校验 |
|---|---|---|---|
| **input（开始）** | 输入变量表：名称/类型/必填/默认值/描述 | 行编辑器（类型下拉用标准 Select）；作为全局变量源注入 VarCascader | 变量名唯一；类型受控词表 |
| **end（结束）** | 输出映射：`{输出键: 引用}` 多行 | 映射行（左键名+右引用级联） | 引用有效性（目标删除→INVALID 阻止发布，既有规则） |
| **reply** | 回复内容（富文本+引用插值）、回复目标 | PromptArea（既有）+引用插入 | 非空 |

### 模型/推理族
| 节点 | 关键字段 | 控件 | 校验 |
|---|---|---|---|
| **llm** | 模型（资源选择器，Model 是节点配置不是独立节点——既有冻结决策）、temperature/maxTokens、系统提示词、用户提示词（引用插值）、结构化输出 schema、批处理模式（遍历列表变量聚合） | ModelPicker（复用资源选择器组件）+ PromptArea + 输出 schema 编辑器 | 模型资源 enabled；提示词非空；批处理须声明列表变量 |
| **knowledge-retrieval** | 知识库（资源选择器）、query（引用）、topK、相似度阈值、输出字段选择 | 资源选择器+数值步进 | 知识库存在且 enabled |
| **query-rewrite** | 原始 query（引用）、改写策略（扩展/纠错/意图归一）、模型 | 单选策略卡+引用 | 失败策略走 execution.onError（不再静默吞错，审计 B 相关修复点） |

### 逻辑/数据族
| 节点 | 关键字段 | 控件 | 校验 |
|---|---|---|---|
| **condition** | 条件分支列表（每分支：条件组+目标）、默认分支 | 条件构建器（与 Trigger filter 同构，抽取共享，见 03 文档 §4）；拖拽排序保留 | 分支覆盖完整；必有默认 |
| **decision-class** | 分类维度（引用质检准则集）、判定输出 | 准则集选择器+输出映射 | 准则集版本有效 |
| **transform** | 映射行：目标键 ← 引用/受限表达式 | 映射行编辑器（与输入/输出映射引擎同语法，03 §5） | 表达式合法性 |
| **code-write** | 代码（受限沙箱）、输入绑定、输出声明 | 代码编辑器（等宽+行号）+输入输出表 | 沙箱执行通过；异常不再静默（显式进 onError） |
| **memory-variable** | 变量读/写、作用域 | 读写模式切换+变量级联 | 变量已声明 |
| **data-read** | 数据资产（仅创建者身份，D7）、窗口/抽样（与 Task 同词表）、字段选择 | 资产选择器+窗口选择 | 资产存在；身份校验后端强制 |

### 工具/集成族
| 节点 | 关键字段 | 控件 | 校验 |
|---|---|---|---|
| **tool** | 工具（资源选择器）、参数映射（声明式配方）、副作用级别展示（read / write-reversible / write-irreversible，ADR-R07） | 参数映射行+副作用徽标（写型红色警示） | 工具 enabled；写型工具必须显式确认幂等键 |
| **mcp-call** | MCP 服务（资源选择器）、工具发现（列工具）、参数 | 服务选择→工具下拉（动态拉清单）→参数映射 | 服务连通；工具存在 |
| **notification** | 渠道（出站通知）、模板、接收人 | 渠道选择+模板编辑器 | 出站走 egress 策略（既有） |
| **create-record** | 记录类型、字段映射（业务落库，如质检结果投影） | 映射行 | 字段与目标定义对齐 |

### 编排族
| 节点 | 关键字段 | 控件 | 校验 |
|---|---|---|---|
| **workflow-fixed** | 已发布工作流（钉版本或最新已发布，D5）、输入映射 | 工作流选择器+版本策略单选+映射行 | 目标工作流已发布 |
| **workflow-select** | 候选工作流集、选择条件（运行时决定走哪个） | 候选多选+条件构建 | 候选均已发布 |
| **workflow-exec** | 动态工作流引用（表达式）、输入映射 | 引用级联 | 引用类型=已发布工作流 |
| **loop** | 遍历对象（列表引用）、body 回边、done 出口、单轮超时、最大轮数 | 循环变量声明+回边可视化提示（D4 单画布回边） | 回边白名单校验（validator 既有） |
| **wait-review** | 审核人/组、超时策略（自动通过/驳回）、**外部回调（置灰预留，D3）**、表单（可选绑定 Form） | 审核人选择+超时策略+表单选择 | 审核人有效；V1 仅人审+定时 |

**退役（仅加载迁移）**：agent / agent-select / agent-exec（D8 已合并进 workflow 三兄弟，旧图加载时一次性改写）。

## 6. 试运行与调试体验（替代手绘验证）

1. **Test Run 覆盖层**（既有机制升级）：按可达祖先输出与 Start 输入自动生成推荐输入表单，用户只改想改的——替代手填 mock JSON；
2. **节点单测**：保留单节点执行，但输入表单由该节点引用变量自动推导（同上）；
3. **运行结果钻取**：试运行结束后每节点卡显示状态，点开即看该节点输入/输出/耗时（复用 `/trace` 组装端点，`runs.py:305-317`）；
4. **事件流**：SSE 断线按 sequence 重放（`GET /runs/{id}/events?after=`，既有决策），不重造轮子。
