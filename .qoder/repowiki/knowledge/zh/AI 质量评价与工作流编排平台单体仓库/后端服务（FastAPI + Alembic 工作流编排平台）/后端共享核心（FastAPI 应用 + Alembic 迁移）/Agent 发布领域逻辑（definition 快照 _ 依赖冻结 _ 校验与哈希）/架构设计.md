单文件领域模块 `server/app/agent_release.py`，不暴露 HTTP 接口，仅被上层 router/service 调用，职责按功能划分为四个子域：
- 快照组装：`build_definition` 根据 `agent.type` 分支生成 autonomous（rolePrompt/modelRef/skills/tools/workflows/knowledges）或 workflow-based（workflowId/graph/members）定义；`build_common_config` / `build_common_config_dict` 从原始 config 提取 conversation、memoriesSchema、knowledgeFallback 形成 CommonAgentConfig 快照。
- 依赖冻结：`freeze_dependencies` 通过 `_resolve_tool/_resolve_workflow/_resolve_knowledge` 将运行时引用解析为确定版本并标记 FROZEN/MISSING/DISABLED/UNPUBLISHED/NO_READY_VERSION，autonomous 路径遍历 tools/workflows/knowledges/modelRef，workflow 路径遍历 members、graph.nodes 中的 tool/knowledge-retrieval/llm 节点。
- 不可变标识：`artifact_hash` 对 definition+commonConfig+dependencies 三要素做 JSON 序列化后 SHA-256，作为 AgentVersion 的 artifact_id。
- 发布校验：`validate_publish` 集中检查名称长度、prompt/model/graph/members/memory 等业务规则，返回 `list[dict]` issues 供调用方聚合展示。
- 版本号：`next_version_no` 基于 `AgentVersion.count()` 提供递增序号。
依赖方向单向向外：仅依赖 `models`（ORM）、`schemas.WorkflowDefinition`（Pydantic v2 图模型）、`validator.validate`（工作流图校验），不反向依赖路由或编排层；definition 快照通过 `json.loads(json.dumps(wf.draft_definition))` 深拷贝草稿图，确保发布后编辑草稿不影响已发布版本。
