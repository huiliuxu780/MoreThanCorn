模块由两部分通过同一份 SQLAlchemy DeclarativeBase 绑定：
- `server/app/` 是 FastAPI 运行时入口，`main.py` 在 lifespan 中初始化 ModelProvider/Model、拉起同进程 Worker（`runner.start_worker()`），并按域挂载 `routers/` 下的工作流、注册表、运行、业务、资源、管理、Agent 路由；`models.py` 集中定义 Workflow/Version、Tool/Detail、Model/Provider、Run、JobQueue、Schedule、Agent、Connection、KnowledgeSource、QualityResult 等实体，主键使用 `new_id()` 生成 32 位 hex，时间字段 UTC；`db.py` 暴露 `SessionLocal` 与 `get_db` 依赖注入。
- 执行层 `runner.py` 实现 DAG 状态机与十类节点 executor 分派，`agent_runtime.py` 在其之上叠加 autonomous ReAct 循环封装 LLM 调用与护栏，两者均通过 `emit(db, run_id, type, payload)` 写入 `run_event` 并以 sequence 单调递增，SSE 客户端据此重放事件流。
- 领域逻辑（如 agent_release_domain 的快照/依赖冻结/发布校验）以独立文件组织，被 routers 与 runner 共同引用，形成「路由→领域→ORM」的单向依赖。
- `server/alembic/` 迁移侧通过 `env.py` 将 `sys.path.insert` 引入 `app.db.Base.metadata` 作为 `target_metadata`，使迁移脚本与运行时 ORM 模型保持同一份 schema；`versions/` 按业务演进顺序存放增量脚本（初始 schema → agent/table → model_version → resource_management_p1 → quality_result_evidence 等）。
