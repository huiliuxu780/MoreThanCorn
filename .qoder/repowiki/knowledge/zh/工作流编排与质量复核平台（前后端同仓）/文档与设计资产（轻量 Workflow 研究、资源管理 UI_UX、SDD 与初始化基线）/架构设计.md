本模块为纯文档与原型资产目录，按主题划分为三个并列子目录，彼此无代码依赖：
- `docs/research/lightweight-workflow-system/`：以“三证据链”（quickservice UI 实操截图、CDP Network 抓包 JSON、Sim 源码分析）驱动的设计研究目录，包含 01–17 号编号的渐进式设计文档（产品交互、网络契约、Sim 架构、目标系统架构、前端设计、DSL、Registry、Runner-Scheduler-Worker、日志事件、数据模型、安全部署、POC 计划等），并通过 `contracts/openapi.yaml`、`run-event.schema.json`、`workflow-definition.schema.json` 固化 API 与 DSL 契约；`evidence/` 下按 network/screenshot 分类存放 CDP 抓包产物、截图与脱敏脚本，`evidence-ledger.md` 作为证据台账。
- `uiux/`：围绕“资源管理（AI Resources / Data Resources）”的需求理解与设计 Spec，配套 `prototype/` 静态 HTML+CSS+JS 原型（可直接浏览器打开或 `python3 -m http.server` 预览），文档编号 00–05 对应 requirement-understanding、requirement、design-spec、backend-frontend-design、verification-cases、agent-runtime-design。
- `docs/sdd/`：Spec-Driven Development 路线图，通过 `00-index.md` 总索引串联 A–E 阶段规格、节点总纲、验收报告与生产就绪门禁，`deliverables/` 集中交付物（schema/openapi/错误码），`acceptance/` 记录各阶段验收证据。
- `初始化doc/`：项目启动时产出的冻结基线文档，包括 CODEX_HANDOFF、DESIGN_SPEC、IMPLEMENTATION_SPEC、产品架构冻结文档及 Feature Spec Template，作为后续开发对照基线。
依赖方向单向：`docs/research` 中的设计文档引用 `contracts/` 契约文件；`uiux/` 的原型仅依赖本地静态资源；`docs/sdd/` 与 `初始化doc/` 被其他模块视为只读基线。
