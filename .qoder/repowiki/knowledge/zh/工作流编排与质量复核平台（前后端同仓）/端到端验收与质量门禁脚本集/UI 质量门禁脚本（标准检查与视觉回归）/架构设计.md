模块由两个独立的 Node.js ESM 脚本组成：`check-ui-standard.mjs` 递归遍历 `src/` 下所有 TSX/JSX 文件，用预定义的正则模式（原生 select/input/textarea、window.alert/confirm/prompt、手搓 switch）匹配违规代码，并通过 `ui-allowlist.json` 维护只减不增的豁免台账；同时校验 `components/wf` 目录仅允许登记的文件（controls.tsx、sections.tsx），新增需先更新 SDD §6.2。`check-visual-regression.mjs` 启动 headless Chrome 访问运行中的 dev server（5173）与后端（8100），动态创建名为 VIS-REG 的工作流并截图 canvas、大模型/循环迭代/等待人审三个 drawer 场景，使用 `pixelmatch` 与 `pngjs` 将截图与 `scripts/visual-baseline/` 下的 PNG 基线比对，差异率超过 0.5% 即失败并输出热图到 `/tmp/vr-diff-*.png`；同时在 DOM 中读取计算样式断言节点宽度（300px）、圆角（8px）、画布背景（#EEF1F6）、抽屉宽度（360px）等设计令牌。依赖方向单向：脚本 → 文件系统 + 本地 HTTP API + Puppeteer，无业务逻辑耦合。
