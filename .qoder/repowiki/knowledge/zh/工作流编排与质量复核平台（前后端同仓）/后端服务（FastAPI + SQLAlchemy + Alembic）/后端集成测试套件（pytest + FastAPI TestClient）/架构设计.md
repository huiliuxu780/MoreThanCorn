测试以 `conftest.py` 固定 `WF_PAR_RUN=1` 确保节点并发度确定性；每个测试文件通过模块级 `TestClient(app)` 直接调用 `/api/*` REST 接口，并在模块作用域调用 `app.runner.start_worker()` 启动进程内 worker 线程消费 JobQueue，使异步 Runner/Agent 执行可达终态。
- 执行层：`test_runner.py` 验证分支/转换/mock-llm/SSE 事件序列与递归守卫；`test_agent_runtime.py` 覆盖 autonomous/dialogue/expert-group 三型 Agent 运行、挂载健康检查与发布同步。
- 业务层：`test_business.py` 覆盖规则引擎派生、复核历史、批量任务与 Cron 调度。
- 资源与调度层：`test_p2.py` 验证 schedule tick、tool test、连接引用阻断、metrics 与认证中间件；`test_resources.py` 覆盖六类资源 CRUD、toggle、删除保护链与 test executor。
- 契约层：`test_contracts.py` 直接调用 `app.validator.validate` 校验 WorkflowDefinition 七条规则，并通过 quickservice 黄金 fixture 保证向后兼容。
- 数据断言统一通过 `app.db.SessionLocal` 直连 ORM 模型（Run、Schedule、CallRecord、JobQueue、WorkflowVersion、QualityResult 等）验证状态，而非仅依赖 API 返回值。
- 质检专用构件集中在 `_quality_setup.py`，提供 `make_quality_workflow` / `make_definition_version` / `make_rule_version` / `make_asset` / `make_quality_task` 等工厂函数，用于组装满足新校验（定义版本必填/规则绑定/create-record）的任务。
