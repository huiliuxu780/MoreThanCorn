三个并列的 Node.js ESM 脚本（accept-browser-1/2/3.mjs），每个独立启动一个 headless Chromium 实例，通过 puppeteer-core 直接操作 http://localhost:5173 的前端页面，构成按阶段划分的端到端流水线：阶段1访问 /config/tasks/:id 触发 Run 并轮询表格行中的状态 badge（queued→running→success/partial/failed/completed/cancelled）；阶段2进入 /quality/results 列表→详情→复核→提交→刷新校验持久化；阶段3重启后端后再次访问 /quality/results 与 /settings/connections 确认数据持久化及真实数据库回显。脚本之间无共享模块，仅约定截图证据目录 /tmp/accept-evidence/*.png 与默认 admin/admin 登录凭据，依赖顺序由外部 CI/手动调用顺序保证。
