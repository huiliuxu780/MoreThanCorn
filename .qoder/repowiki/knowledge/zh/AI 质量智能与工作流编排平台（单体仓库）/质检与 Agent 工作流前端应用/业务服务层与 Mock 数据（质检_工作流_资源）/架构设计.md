模块按职责划分为四个子层：
- 业务服务层 `services/mock-service.ts`：以内存数组为数据源，实现 listQualityResults/getQualityResult/getQualityOverview/getAgentAnalysis/listTasks/listRuns/listExecutions/listAgents/listTools/listDataAssets/listResultRules/listConnections 等接口，统一通过 delay(LATENCY) 模拟网络延迟，使用 paginate/matchSearch/parseListFilters 实现分页、搜索与过滤，并按 tab/filters 组合筛选；聚合函数在本地计算 KPI、趋势、Top Issues 与场景质量。
- 真实 API 客户端 `services/wf-api.ts` 与 `services/resource-api.ts`：封装 fetch 调用，统一通过 WF_BASE 环境变量路由到后端 /api/workflows、/api/runs、/api/agents、/api/quality-results、/api/data-assets、/api/connections 等路径；wfApiToken() 从 localStorage 或 VITE_WF_API_TOKEN 注入 Bearer Token；realRunDetail/realQualityResults/bizApi 将后端响应适配为 @/domain/types 中的 Run/InteractionExecution/QualityResult 等类型；resource-api.ts 进一步抽象 AI 与数据两类资源的 CRUD 及定义/连接管理。
- 权限与数据层 `services/rbac.ts` 提供 Permission 联合类型与 can/actionVisibility 方法，原型阶段默认放行，可替换为真实权限适配器；`mocks/catalog.ts` 集中部门/班组/坐席/品牌/品类/问题/准则目录与 criterionSeverity 映射；`mocks/scenarios.ts` 定义四类质检场景模板（含对话片段、Section/Criterion、BusinessFact）；`mocks/data.ts` 用确定性伪随机 mulberry32(20260821) 生成 14 天的 qualityResults/tasks/runs/executionsByRun/agents/tools/dataAssets/resultRuleSets/connections 等种子数据，并通过 scenarioIdByInteraction 建立 Interaction→Scenario 的关联。
依赖方向：mock-service → mocks/* + @/domain/types + @/lib/list-filters；wf-api/resource-api → @/domain/types；rbac 独立无外部依赖。
