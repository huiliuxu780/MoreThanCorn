测试按功能域拆分为独立文件：test_runner.py（P1 Runner 分支/转换/mock-llm/SSE/递归守卫）、test_phase_a.py（SDD A-01~A-09：版本锁定、注册表、通知节点、条件运算符、调用记录、乐观锁、名称长度、Agent 路由与异步入队）、test_agent_runtime.py（autonomous/dialogue/expert-group 三型 Agent 运行、挂载健康检查、发布同步）、test_business.py（规则引擎派生、复核历史、批量任务与 Cron 调度）、test_p2.py（schedule tick、tool test、连接引用阻断、metrics、认证中间件）、test_p5_nodes.py（knowledge-retrieval 与 mcp-call 节点联动及依赖快照）、test_resources.py（六类资源 CRUD、toggle、删除保护链、test executor）、test_contracts.py（WorkflowDefinition 七条校验规则 + quickservice 黄金 fixture 兼容）。所有用例通过 `fastapi.testclient.TestClient(app)` 直接调用 `/api/*` 接口，并借助 `app.runner.start_worker()` 启动进程内 worker 线程消费 JobQueue；数据库断言使用 `app.db.SessionLocal` 直连 ORM 模型（Run、Schedule、CallRecord、JobQueue、WorkflowVersion 等）验证状态。测试数据通过模块内工厂函数（如 `_wf_with_sink`、`make_wf`、`_build_wf`）在运行时动态构造最小工作流图，避免外部 fixture 依赖。
