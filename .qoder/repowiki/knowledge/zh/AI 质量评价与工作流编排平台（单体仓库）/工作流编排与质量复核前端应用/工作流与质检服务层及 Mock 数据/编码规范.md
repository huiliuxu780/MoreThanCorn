- 所有列表查询统一接收 `ListParams`（search/page/pageSize/sort/filters/tab），内部先 `parseListFilters` 解析 filters，再链式 filter 叠加条件，最后调用 `paginate` 返回 `ListResponse<T>`。
- 每个导出 API 函数都通过 `delay(value)` 包裹返回值，模拟 120ms 网络延迟，使 Mock 行为与真实异步 API 一致。
- 搜索采用 `matchSearch` 对多字段拼接后做大小写不敏感 includes 匹配，过滤则按 `filters.xxx === value` 精确相等判断。
- 真实 API 客户端统一通过内部 `req<T>(path, init?)` 封装 fetch，自动附加 Content-Type 与 Authorization: Bearer 头，并在非 2xx 时抛出带 status/detail 的 Error。
- Mock 数据文件通过 `mulberry32(seed)` 确定性伪随机生成，确保应用重启后 qualityResults、runs、executionsByRun 等序列稳定可重现。
- 业务主数据（部门/班组/坐席/品牌/品类/问题/准则）集中在 `mocks/catalog.ts` 并以 `as const` 声明，被上层共同引用，避免散落字符串字面量。
