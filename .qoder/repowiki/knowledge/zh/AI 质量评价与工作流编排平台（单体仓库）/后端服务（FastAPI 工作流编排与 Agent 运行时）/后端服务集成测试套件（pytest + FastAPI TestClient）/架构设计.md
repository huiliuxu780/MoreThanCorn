测试按功能域拆分为独立文件，每个文件通过 `TestClient(app)` 直接调用 `/api/*` 接口，并借助 `app.runner.start_worker()` 启动进程内 worker 线程消费 JobQueue，使异步 Runner/Agent 执行可达终态。
- 执行层：`test_runner.py` 验证分支/转换/mock-llm/SSE 事件序列与递归守卫；`test_agent_runtime.py` 覆盖 autonomous/dialogue/expert-group 三型 Agent 运行、挂载健康检查与发布同步；`test_business.py` 覆盖规则引擎派生、复核历史、批量任务与 Cron 调度。
- 资源与调度层：`test_p2.py` 验证 schedule tick、tool test、连接引用阻断、metrics 与认证中间件；`test_resources.py` 覆盖六类资源 CRUD、toggle、删除保护链与 test executor。
- 契约层：`test_contracts.py` 直接调用 `app.validator.validate` 校验 WorkflowDefinition 七条规则，并通过 quickservice 黄金 fixture 保证向后兼容。
- 数据断言统一通过 `app.db.SessionLocal` 直连 ORM 模型（Run、Schedule、CallRecord、JobQueue、WorkflowVersion 等）验证状态，而非仅依赖 API 返回值。
