模块按职责划分为四个子层，依赖方向单向向下：
- 业务服务层 `services/mock-service.ts`：以内存数组为数据源，通过 `delay(LATENCY)` 统一模拟 120ms 网络延迟，使用 `parseListFilters` + `matchSearch` + `paginate` 实现统一的列表分页/搜索/过滤，并在本地聚合 KPI、趋势、Top Issues 与场景质量；导出 `listQualityResults/getQualityResult/getQualityOverview/getAgentAnalysis/listTasks/listRuns/listExecutions/listAgents/listTools/listDataAssets/listResultRules/listConnections` 等接口。
- 真实 API 客户端 `services/wf-api.ts` 与 `services/resource-api.ts`：封装原生 fetch，统一通过 `WF_BASE`（默认 `http://127.0.0.1:8100`）路由到 `/api/workflows`、`/api/runs`、`/api/agents`、`/api/quality-results`、`/api/data-assets`、`/api/connections` 等路径；`wfApiToken()` 从 `localStorage` 或 `VITE_WF_API_TOKEN` 注入 Bearer Token；`realRunDetail/realQualityResults/bizApi` 将后端响应适配为 `@/domain/types` 中的 Run/InteractionExecution/QualityResult 等类型；`resource-api.ts` 进一步抽象 AI 与数据两类资源的 CRUD、定义与连接管理，复用 `wf-api` 的 `WF_BASE` 与 `wfApiToken`。
- 权限与数据层 `services/rbac.ts`：定义 `Permission` 联合类型并提供 `can/actionVisibility` 方法，原型阶段默认放行，可替换为真实权限适配器。
- 种子数据层 `mocks/catalog.ts`（部门/班组/坐席/品牌/品类/问题/准则目录与 `criterionSeverity`）、`mocks/scenarios.ts`（四类质检场景模板含对话片段、Section/Criterion、BusinessFact）、`mocks/data.ts`（基于 `mulberry32(20260821)` 确定性 PRNG 生成 14 天的 qualityResults/tasks/runs/executionsByRun/agents/tools/dataAssets/resultRuleSets/connections 等种子数据，并通过 `scenarioIdByInteraction` 建立 Interaction→Scenario 关联）。
依赖方向：`mock-service` → `mocks/*` + `@/domain/types` + `@/lib/list-filters`；`wf-api`/`resource-api` → `@/domain/types`；`rbac` 独立无外部依赖。
