- 每个测试文件顶部通过 `TestClient(app)` 创建全局 client，并在模块级调用 `start_worker()` 保证异步 runner 可用。
- 工作流构造采用“获取定义 → 追加 input/llm/transform/end 节点 → put /draft”三步模式，并通过 `baseRevision` 实现并发写冲突测试。
- 对异步 Agent/Runner 执行统一封装 `wait_terminal(agent_id, run_id, timeout=30.0)` 轮询终态（succeeded/failed/cancelled），超时抛出 AssertionError。
- 测试数据 ID 通过 `u(prefix)` 工具生成带 UUID 前缀的唯一名，避免并发测试间资源冲突。
- 需要绕过真实 LLM 的用例通过 `monkeypatch.setattr` 替换 `app.agent_runtime._chat_completion` 与 `_resolve_base_secret`，返回固定响应。
- 对数据库状态的断言使用 `SessionLocal()` 直接查询 ORM 模型（Run、Schedule、CallRecord、JobQueue、WorkflowVersion），而非仅依赖 API 返回值。
