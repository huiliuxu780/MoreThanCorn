## 1. 整体方案

仓库采用**纯环境变量 + 前端构建期常量**的轻量配置体系，没有引入 dotenv、pydantic-settings、.env 文件等第三方配置框架。

- **后端（FastAPI）**：所有运行期配置通过 `os.environ.get` 读取，集中在 `server/app/config.py` 暴露 `DATABASE_URL`；认证 token、LLM 凭据、加密密钥等敏感项在各自模块内直接读环境变量。
- **前端（Vite+React）**：构建期常量集中放在 `src/config/enterprise.ts`（企业时区/语言）和 `src/config/ui-terms.ts`（导航文案、状态标签、状态→语义色映射）；运行时 API 地址与开关通过 Vite 注入的 `import.meta.env.VITE_*` 变量获取。
- **数据库迁移（Alembic）**：复用后端 `app.config.DATABASE_URL`，并通过 `WF_DATABASE_URL` 环境变量覆盖。

## 2. 关键文件与位置

| 层次 | 文件 | 职责 |

| 后端核心配置 | `server/app/config.py` | 定义 `DATABASE_URL`，按 pytest 环境切换默认值 |
| 后端数据库接入 | `server/app/db.py` | 使用 `create_engine(DATABASE_URL, pool_pre_ping=True)` 创建引擎 |

## 3. 架构与约定

### 3.1 后端环境变量命名规范
所有后端配置统一以 `WF_` 前缀命名，便于区分业务域：
- `WF_DATABASE_URL` — PostgreSQL 连接串（开发默认 `postgresql+psycopg://rivers@127.0.0.1:5432/wf_dev`，pytest 下走 `wf_test`）
- `WF_API_TOKEN` — 可选的 Bearer Token，设置后 `/api/*` 强制鉴权
- `WF_LLM_BASE_URL` / `WF_LLM_API_KEY` — LLM 调用基址与密钥
- `WF_SECRET_KEY` — Fernet 对称加密密钥，用于持久化 Connection 的 secret

### 3.2 配置分层策略
- **应用级配置**（数据库、API 端口、CORS 源）：通过环境变量注入，不入库。
- **运行时可编辑配置**（Connection、ModelProvider、Tool、Schedule、Agent 配置）：写入数据库，由 admin 接口 CRUD，运行时由 worker/runner 动态读取。其中 Connection.secret 经 `_encrypt()` 用 `WF_SECRET_KEY` 加密存储，更新时留空表示保留原密钥。
- **前端构建期常量**：`enterprise.ts` 中的 timezone/locale 在编译时固化，注释明确“时间统一按企业时区展示，不在页面组件内硬编码”。
- **前端运行时开关**：`VITE_WF_API=1` 决定是否启用真实后端；`VITE_WF_API_BASE` 指定后端地址；`VITE_WF_API_TOKEN` 作为请求头附加。

### 3.3 默认值与环境推断
- 后端 `config.py` 通过检查 `sys.modules` 中是否存在 `pytest` 自动切换测试库 URL，无需额外环境变量。
- Alembic 迁移同样遵循此逻辑：优先 `WF_DATABASE_URL`，否则回退到 `app.config.DATABASE_URL`。
- CORS 白名单硬编码为 `localhost:5173`，未提供环境变量覆盖。

### 3.4 安全约束
- 敏感信息（LLM key、Connection secret、API token）一律通过环境变量传入，不写入库或源码。
- Connection 的 secret 在落库前经 Fernet 加密；若 `WF_SECRET_KEY` 未设置则降级为明文存储（代码显式捕获异常并返回原文），属于开发模式行为。
- 前端 token 优先从 `localStorage.getItem("wf_api_token")` 读取，其次回退到 `VITE_WF_API_TOKEN`。

## 4. 约定与约束

- **环境变量命名必须带 `WF_` 前缀**：当前所有后端配置均如此，新增配置应沿用该约定。
- **数据库 URL 必须通过 `WF_DATABASE_URL` 注入**：`db.py`、`alembic/env.py` 都依赖该变量名，不可随意改名。
- **RBAC 鉴权是可选开关**：仅在 `WF_API_TOKEN` 非空时生效，空字符串即放行所有 `/api/*` 请求。
- **前端禁止硬编码产品文案与状态语义**：`ui-terms.ts` 的注释声明“导航结构冻结，不允许新增一级入口”，状态中文文案必须存在，颜色只是辅助语义。
- **企业级部署配置集中管理**：`enterprise.ts` 注释引用 Implementation Spec §5，要求时间统一按企业时区展示，组件不得自行硬编码。
- **前端 API 客户端统一封装**：页面禁止裸 fetch，所有后端调用必须经过 `wf-api.ts` 导出的 `wfApi/runApi/scheduleApi/bizApi` 等命名空间，保证统一错误处理与 token 注入。
- **CORS 源需手动维护**：当前仅允许 `http://localhost:5173` 与 `http://127.0.0.1:5173`，生产环境需修改 `main.py` 中的 `allow_origins` 列表。

## 5. 缺失与改进点

- 没有 `.env` 模板文件或配置文档说明，新开发者需自行查找各 `WF_*` 变量含义。
- 缺少配置校验层（如 pydantic-settings），环境变量拼写错误会静默使用默认值。
- 前端构建期配置（`VITE_*`）未做类型约束，`import.meta.env` 访问处使用了 `as any` 绕过 TS 检查。
- 没有 feature flag 机制，功能开关目前仅靠 `VITE_WF_API=1` 一个布尔位控制。
