关键设计决策
决策依据与取舍
两个列表页 + 页内 Tabs，而非六个独立页Spec V1.4 明确「Header + Toolbar + Tabs + Card Grid」；Tabs 携带计数，类型切换不丢筛选上下文。
六类资源共用 ResourceCard 骨架强类型体现在副标题、Metadata 与表单字段；骨架统一降低认知与维护成本。
生命周期与健康度正交双状态文档未定义状态机；沿用现有 Health 语义（Healthy/Degraded/Error），测试失败只降健康度、不自动停用。
删除 = 拦截对话框 + 引用清单需求要求「使用中不可删除」；列出引用方并给出解决路径，优于静默置灰。
无版本类型详情用「变更记录」MCP/Knowledge/Datasource/Asset 不设版本机制（需求 §版本策略），审计诉求由变更记录承接。
向导第 3 步测试强制通过创建方式「选择类型 → 表单 → 测试 → 保存」中测试是必经环节；失败可回改，保证入库资源即可用。

需求理解与开放问题详见 uiux/00-requirement-understanding.md。原型数据均为示意；「演示」标注处为刻意安排的交互分支（删除拦截 / 测试失败 / 无引用删除）。
